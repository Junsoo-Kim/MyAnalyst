# 검색 설정 비교 평가 (BM25 토큰화, 하이브리드 RRF)

같은 문서·같은 질의로 검색 설정만 바꿔 비교한다. OpenAI를 호출하지 않는다.

## 실행

```bash
# 1) 데이터셋 (호스트, requests + beautifulsoup4). 기사 원문은 evals/data/corpus.local.jsonl에만 쓴다(.gitignore).
python services/knowledge/evals/build_retrieval_dataset.py --articles 20

# 2) 평가 (knowledge 이미지 안에서. 현재 코드를 /src로 마운트한다. /app은 모델 캐시가 있어 덮지 않는다)
OPENAI_API_KEY=stub docker compose -p myanalyst-eval up -d --wait etcd minio milvus opensearch
docker compose -p myanalyst-eval run --rm --no-deps -v ./services/knowledge:/src -e PYTHONPATH=/src -w /src \
  knowledge python -m evals.retrieval_comparison_eval
OPENAI_API_KEY=stub docker compose -p myanalyst-eval down -v
```

평가용 Milvus 컬렉션과 OpenSearch 인덱스를 따로 만들고 끝나면 지운다. 운영 인덱스(`myanalyst-chunks`)는 건드리지 않는다.
결과는 `evals/results/retrieval_comparison.json`(질의별 순위 포함)에 남는다.

## 방법

- **문서:** `ingest_sources/셀트리온_news_links_1.txt`의 링크를 앞에서부터 받아, 본문 추출 품질 기준을 통과한 기사 N개를 쓴다. 청크는 문장 단위로 350자 근처에서 자른다(문장을 쪼개지 않음).
- **질의(사람이 고르지 않음):** 기사마다 첫 문장(리드)을 건너뛰고, 조건을 만족하는 문장 중 앞쪽 1개와 가운데 1개를 고른다. 조건은 다음과 같다.
  - 40자 이상
  - 조사가 붙은 어절 2개 이상
  - 명사 위주 단어 5개 이상
  
  한 문장에서 질의 두 가지를 만든다.
  - `verbatim`: 문장의 어절을 그대로 앞에서 5개.
  - `keyword`: 어절 끝 조사를 떼고 서술어를 뺀 단어 5개. 보고서 생성 파이프라인이 LLM으로 만드는 검색 키워드와 같은 모양(조사 없는 명사 나열)이다.
  - 같은 보도자료를 여러 매체가 실어 질의가 겹치면 한 번만 쓴다.
- **정답:** 질의를 만든 문장이 들어 있는 청크. 같은 문장이 다른 매체 기사에도 있으면 그 청크도 정답이다.
- **설정:** 모두 상위 20개를 가져와 상위 10개로 평가한다(운영 `SEARCH_TOP_K`=20, `RRF_K`=60).

| 설정 | 내용 |
|---|---|
| `dense` | KLUE-BERT(`klue/bert-base`) 임베딩 + Milvus FLAT/L2 |
| `bm25_standard` | OpenSearch 기본(standard) 분석기로 원문 색인·질의 (토큰화 수정 전) |
| `bm25_wordpiece` | KLUE-BERT WordPiece로 미리 토큰화, whitespace 분석기 (현재 운영, `hybrid_search._tokenize`) |
| `hybrid_standard` | dense + bm25_standard, RRF |
| `hybrid` | dense + bm25_wordpiece, RRF (현재 운영) |

- **지표:**
  - Hit@1, Hit@10: 정답 청크가 상위 1개/10개 안에 있는 질의 비율
  - MRR@10: 정답 순위의 역수 평균
  - Miss@10: 1 − Hit@10

## 결과 (2026-10-21, 기사 20개 · 청크 97개 · 질의 문장 35개)

`keyword` 질의 (파이프라인이 실제로 쓰는 질의 모양):

| 설정 | Hit@1 | Hit@10 | MRR@10 | Miss@10 |
|---|---|---|---|---|
| dense | 0.171 | 0.800 | 0.380 | 0.200 |
| bm25_standard | 0.714 | 0.971 | 0.787 | 0.029 |
| bm25_wordpiece | **0.829** | **1.000** | **0.893** | **0.000** |
| hybrid_standard | 0.400 | 0.971 | 0.607 | 0.029 |
| hybrid | 0.429 | 0.943 | 0.622 | 0.057 |

`keyword` 질의를 숫자 포함 여부로 나눠 BM25 두 설정을 비교하면 다음과 같다.

| | 질의 수 | bm25_standard MRR@10 | bm25_wordpiece MRR@10 | Hit@1 |
|---|---|---|---|---|
| 숫자 포함 | 19 | 0.744 | **0.939** | 0.684 → 0.895 |
| 숫자 없음 | 16 | 0.839 | 0.839 | 0.750 → 0.750 |

`verbatim` 질의(문서와 어형이 같음)에서는 두 BM25가 비슷하다. standard는 MRR 0.945, wordpiece는 0.931이다.

## 해석

1. **토큰화 수정의 효과는 어형이 다를 때만 나타난다.** 문서의 어절을 그대로 쓴 질의에서는 두 분석기가 비슷하다. 조사를 뗀 키워드 질의에서는 WordPiece가 Hit@1을 0.714에서 0.829로, MRR을 0.787에서 0.893으로 올렸다. 차이는 숫자가 들어간 질의에 몰려 있다(MRR 0.744 → 0.939).
   - 예를 들어 질의 "자금 252억6000만원"을 보자. 문서에는 "자금은 252억6000만원으로"라고 쓰여 있다.
   - 기본 분석기는 "252억6000만원으로"를 한 토큰으로 보기 때문에 질의의 "252억6000만원"과 맞지 않는다.
   - WordPiece는 "##으로"를 따로 떼어 내므로 둘이 맞는다.
   - 금융 기사에서 수치 뒤에는 조사가 붙는 경우가 많다.
   - 실제 토큰(OpenSearch `_analyze`, KLUE-BERT tokenizer로 확인):

     | | 문서 "자금은 252억6000만원으로" | 질의 "자금 252억6000만원" |
     |---|---|---|
     | standard | `자금은` `252억6000만원으로` | `자금` `252억6000만원` → 겹치는 토큰 없음 |
     | WordPiece | `자금` `##은` `252` `##억` `##60` `##00` `##만` `##원` `##으로` | `자금` `252` `##억` `##60` `##00` `##만` `##원` → 7개 겹침 |
2. **하이브리드는 Dense만 쓰던 원래 방식보다는 크게 낫다.** 키워드 질의 기준으로 Hit@10이 0.800에서 0.943으로, MRR이 0.380에서 0.622로 올랐다.
3. **이 데이터에서는 BM25 단독이 하이브리드보다 높다.** MRR이 BM25 단독 0.893, 하이브리드 0.622다. 이유는 두 가지로 본다.
   - Dense 쪽이 약하다. `klue/bert-base`는 문장 임베딩용으로 학습한 모델이 아니다(Dense MRR 0.380). 같은 가중치의 RRF에서는 Dense가 BM25의 1위 결과를 아래로 끌어내린다.
   - 질의를 문서 문장에서 만들었기 때문에 단어가 그대로 겹쳐 BM25에 유리하다. 사용자가 다른 말로 바꿔 묻는 경우(Dense가 강한 경우)는 이 평가에 들어 있지 않다.

## 한계

- **규모가 작다.** 질의 35개라 질의 하나가 Hit 0.029에 해당한다. 소수점 둘째 자리 차이는 의미 있게 보기 어렵다.
- **known-item 질의라 어휘 일치에 유리하다.** 다른 말로 바꾼 질의나 질문형 질의가 없다.
- **조사 떼기 규칙에 잡음이 있다.** 예: "공매도" → "공매". 서술어 판별도 어미 목록으로 하므로 일부 명사("보고서")가 빠진다.
- **본문 추출이 일반 규칙이다.** 매체별 광고·관련 기사 문구가 섞일 수 있다.
