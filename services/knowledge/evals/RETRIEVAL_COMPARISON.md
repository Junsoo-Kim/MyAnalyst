# 검색 설정 비교 평가 (BM25 토큰화, 임베딩 모델, 하이브리드 결합)

같은 문서·같은 질의로 검색 설정만 바꿔 비교한다. OpenAI를 호출하지 않는다.

## 실행

```bash
# 1) 데이터셋 (호스트, requests + beautifulsoup4). 기사 원문은 evals/data/corpus.local.jsonl에만 쓴다(.gitignore).
python services/knowledge/evals/build_retrieval_dataset.py --articles 20

# 2) 평가 (knowledge 이미지 안에서. 현재 코드를 /src로 마운트한다. /app은 KLUE-BERT 캐시가 있어 덮지 않는다.
#    비교용 한국어 임베딩 모델은 /hfcache에 받아 둔다)
OPENAI_API_KEY=stub docker compose -p myanalyst-eval up -d --wait etcd minio milvus opensearch
docker compose -p myanalyst-eval run --rm --no-deps -v ./services/knowledge:/src -v <hf-cache-dir>:/hfcache \
  -e PYTHONPATH=/src -w /src knowledge python -m evals.retrieval_comparison_eval
OPENAI_API_KEY=stub docker compose -p myanalyst-eval down -v
```

평가용 Milvus 컬렉션 2개와 OpenSearch 인덱스 2개를 따로 만들고 끝나면 지운다. 운영 인덱스(`myanalyst-chunks`)는 건드리지 않는다.
결과는 `evals/results/retrieval_comparison.json`(질의별 상위 20개 순위 포함)에 남는다.

## 방법

- **문서:** `ingest_sources/셀트리온_news_links_1.txt`의 링크를 앞에서부터 받는다. 본문 추출 품질 기준을 통과한 기사 N개를 쓴다. 광고 자리 표시 문자열은 제거한다. 청크는 문장 단위로 350자 근처에서 자른다. 문장은 쪼개지 않고, 문장 경계는 `.?!` 뒤로 한다.
- **정답 문장 고르기(사람이 고르지 않음):** 기사마다 첫 문장(리드)을 건너뛰고, 아래 조건을 만족하는 문장 중 앞쪽 1개와 가운데 1개를 고른다. 같은 보도자료를 여러 매체가 실어 질의가 겹치면 한 번만 쓴다.
  - 40자 이상
  - 조사가 붙은 어절 2개 이상
  - 명사 위주 단어 5개 이상
- **질의 세 가지(같은 정답 문장에서):**

  | 유형 | 만드는 법 | 원문 단어와 겹치는 비율 |
  |---|---|---|
  | `verbatim` | 문장의 어절을 그대로 앞에서 5개 | 1.00 |
  | `keyword` | 어절 끝 조사를 떼고 서술어를 뺀 단어 5개. 생성 파이프라인이 LLM으로 만드는 검색 키워드와 같은 모양 | 1.00 |
  | `paraphrase` | 원문 단어를 피해 다른 말로 쓴 질문(`paraphrases.jsonl`). 회사·제품 이름은 남긴다. 예: 원문 "항암제 계열 간 마케팅 시너지" → "암 치료 바이오시밀러들을 묶어서 판촉하는 전략" | 0.23 |

  `paraphrase`는 평가 작성자가 검색 결과를 보기 전에 썼다. 작성자가 곧 평가자이므로 편향 가능성이 있다. 겹침 비율은 평가가 자동으로 계산해 기록한다.
- **정답:** 질의를 만든 문장이 들어 있는 청크. 다른 매체 기사에 같은 문장이나 거의 같은 문장(어절 집합 Jaccard 0.8 이상)이 있으면 그 청크도 정답이다. 문장 35개 중 13개가 여기에 해당한다.
- **설정:** 검색기마다 상위 20개를 가져온다(운영 `SEARCH_TOP_K`). 하이브리드는 RRF(`k`=60)로 합친 뒤 상위 20개를 쓴다.

| 설정 | 내용 |
|---|---|
| `dense_klue` | `klue/bert-base` 평균 풀링 + L2 (현재 운영 임베딩) |
| `dense_ko` | `jhgan/ko-sroberta-multitask`(한국어 문장 임베딩용으로 학습된 모델) 평균 풀링 + 코사인 |
| `bm25_standard` | OpenSearch 기본(standard) 분석기로 원문 색인·질의 (토큰화 수정 전) |
| `bm25_wordpiece` | KLUE-BERT WordPiece로 미리 토큰화, whitespace 분석기 (현재 운영, `hybrid_search._tokenize`) |
| `hybrid` | dense_klue + bm25_wordpiece, RRF 1:1 (현재 운영) |
| `hybrid_bm25x2` | dense_klue + bm25_wordpiece, RRF 1:2 |
| `hybrid_ko` | dense_ko + bm25_wordpiece, RRF 1:1 |
| `hybrid_ko_bm25x2` | dense_ko + bm25_wordpiece, RRF 1:2 |

- **지표:** Hit@k는 정답이 상위 k개 안에 있는 질의 비율, MRR@10은 정답 순위의 역수 평균이다. 이 시스템에서 가장 중요한 지표는 **Hit@20**이다. 생성 파이프라인이 검색 결과 20개를 받아 LLM으로 관련성을 다시 채점하므로(Corrective RAG), 정답이 그 20개 안에만 들어오면 된다.

## 결과 (2026-10-21, 기사 20개 · 청크 96개 · 정답 문장 35개 × 질의 3종 = 105개)

질의 유형별 **Hit@20 / MRR@10**:

| 설정 | verbatim | keyword | paraphrase | 전체 |
|---|---|---|---|---|
| dense_klue | 0.914 / 0.474 | 0.829 / 0.359 | 0.971 / 0.520 | 0.905 / 0.451 |
| dense_ko | 0.943 / 0.512 | 0.971 / 0.594 | **1.000** / 0.561 | 0.971 / 0.556 |
| bm25_standard | 1.000 / 0.948 | 1.000 / 0.835 | 0.714 / 0.251 | 0.905 / 0.678 |
| bm25_wordpiece | **1.000 / 0.952** | **1.000 / 0.914** | 0.943 / 0.399 | 0.981 / **0.755** |
| **hybrid (운영)** | 1.000 / 0.688 | 1.000 / 0.656 | **1.000 / 0.605** | **1.000** / 0.650 |
| hybrid_bm25x2 | 1.000 / 0.802 | 1.000 / 0.674 | 0.943 / 0.504 | 0.981 / 0.660 |
| hybrid_ko | 1.000 / 0.701 | 1.000 / 0.731 | **1.000** / 0.549 | **1.000** / 0.660 |
| hybrid_ko_bm25x2 | 1.000 / 0.799 | 1.000 / 0.774 | 0.943 / 0.505 | 0.981 / 0.693 |

상위 20개 안에서 놓친 질의:

| 설정 | 놓친 질의 |
|---|---|
| bm25_wordpiece | paraphrase 2개: "암 치료 바이오시밀러들을 묶어서 판촉하는 전략"(dense_klue는 1위), "실적이 해마다 얼마나 커지고 있나"(dense_klue는 5위) |
| dense_klue | keyword 6개, verbatim 3개, paraphrase 1개 |
| dense_ko | keyword 1개, verbatim 2개 |
| hybrid, hybrid_ko | 없음 (105개 모두 상위 20개 안) |

토큰화 수정 효과(`keyword`, 숫자가 들어간 질의 16개): `bm25_standard` → `bm25_wordpiece`에서 MRR@10이 0.713에서 0.875로, Hit@1이 0.625에서 0.750으로 올랐다.

## 해석

1. **Dense와 BM25는 서로 다른 질의를 놓친다.**
   - BM25는 원문과 단어가 겹칠 때 강하다. verbatim·keyword에서 Hit@20 1.000, MRR 0.91~0.95다. 다른 말로 쓴 질문에서는 35개 중 2개를 상위 20개 밖으로 놓쳤다.
   - Dense는 반대다. 바꿔 쓴 질문은 찾지만, 숫자·고유명사가 많은 키워드 질의를 놓친다.
   - 둘을 합친 하이브리드만 105개 질의를 모두 상위 20개 안에 넣었다. 파이프라인이 실제로 쓰는 기준(Hit@20)에서는 하이브리드가 가장 안전하다.
2. **순위(MRR)는 BM25 단독이 가장 높다.** 단어가 겹치는 질의에서 BM25가 1위로 찾은 결과를, 같은 가중치의 RRF에서 Dense가 아래로 끌어내리기 때문이다. 다만 이 파이프라인은 상위 20개를 LLM이 다시 채점하므로, 1위냐 5위냐는 최종 결과에 영향이 작다.
3. **BM25 가중(1:2)은 득실이 있다.** 단어가 겹치는 질의의 MRR은 오르지만(verbatim 0.688 → 0.802), 바꿔 쓴 질의를 다시 놓치게 된다(Hit@20 1.000 → 0.943). 놓치지 않는 것이 우선이면 1:1이 낫다.
4. **한국어 문장 임베딩은 Dense 단독 성능을 크게 올린다.** Dense 단독 기준으로 전체 MRR이 0.451에서 0.556으로, Hit@20이 0.905에서 0.971로 올랐다. 하지만 하이브리드 안에서의 차이는 작다(전체 MRR 0.650 → 0.660, paraphrase는 0.605 → 0.549). 이 규모에서는 모델을 바꿀 근거로 부족하다.
5. **토큰화 수정은 어형이 다른 질의에서 효과가 있다.** 문서 "자금은 252억6000만원으로", 질의 "자금 252억6000만원"을 예로 들면 다음과 같다. 숫자가 들어간 키워드 질의에서 MRR이 0.713에서 0.875로 올랐다.

   | | 문서 "자금은 252억6000만원으로" | 질의 "자금 252억6000만원" |
   |---|---|---|
   | standard | `자금은` `252억6000만원으로` | `자금` `252억6000만원` → 겹치는 토큰 없음 |
   | WordPiece | `자금` `##은` `252` `##억` `##60` `##00` `##만` `##원` `##으로` | `자금` `252` `##억` `##60` `##00` `##만` `##원` → 7개 겹침 |

## 결정에 쓸 수 있는 질문

- **실제 검색 질의가 항상 LLM이 만든 키워드(원문 어휘와 겹침)라면** BM25 단독도 Hit@20을 잃지 않는다. 그 경우 Dense를 빼면 knowledge 이미지(torch, 모델), Milvus, 임베딩 연산을 없앨 수 있다.
- **바꿔 쓴 표현이 섞인다면** BM25 단독은 그만큼 놓친다. Corrective RAG의 `rewrite_query`가 다시 쓰는 질의, 앞으로 사용자 질문을 검색에 쓰는 경우가 여기에 해당한다. 이번 데이터에서는 바꿔 쓴 질의 35개 중 2개를 놓쳤다.

## 한계

- **규모가 작다.** 유형당 35개라 질의 하나가 0.029에 해당한다. 소수점 둘째 자리 차이는 의미 있게 보기 어렵다.
- **paraphrase 질의는 한 사람(평가 작성자)이 썼다.** 겹침 비율은 0.23이다.
- **실제 운영 질의를 쓰지 않았다.** LLM 키워드, `rewrite_query` 결과로 평가하지 않았다. 그러려면 OpenAI 호출이 필요하다.
- **규칙 잡음이 있다.** 조사 떼기(예: "공매도" → "공매"), 서술어 판별, 본문 추출 모두 일반 규칙이다.

## 다음 단계 후보

- **데이터를 늘린다.** 링크 파일 3개(4,500개)에서 기사 100~200개, 정답 문장 200개 이상을 만든다. paraphrase는 다른 사람이 쓰거나 LLM으로 생성한다.
- **운영 질의로 측정한다.** 생성 파이프라인이 실제로 만든 키워드와 재작성 질의를 기록해 같은 평가에 넣는다.
- **임베딩 모델을 다시 비교한다.** 늘린 데이터에서 `dense_ko`가 하이브리드 안에서도 낫다면 운영 임베딩 교체를 검토한다. 교체하려면 Milvus 재색인과 차원 확인이 필요하다.
