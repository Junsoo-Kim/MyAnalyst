# 검색 설정 비교 평가 (Dense / BM25 / 하이브리드)

같은 문서·같은 질의로 검색 설정만 바꿔 비교한다. 데이터는 두 가지다.
- **자체 데이터:** 셀트리온 뉴스, 정답 문장 300개 × 질의 3종
- **공개 벤치마크:** Ko-StrategyQA, 질의 592개, 사람이 정답 라벨링

OpenAI는 호출하지 않는다. 결과는 평균, 95% 신뢰구간, 짝지은 유의성 검정으로 낸다.

## 한눈에 보기

| 비교 | 자체 데이터 (질의 900개) | 공개 벤치마크 (질의 592개) |
|---|---|---|
| **도입 전후: Dense 단독 → 하이브리드** (정답 후보 20개 안 포함률, Hit@20) | **48.2% → 91.9%** (+43.7%p [+39.8, +47.4], p<0.001) | **61.1% → 85.3%** (+24.2%p [+20.6, +27.9], p<0.001) |
| 〃 순위 품질 (MRR@10 / nDCG@10) | MRR 0.245 → 0.515 (p<0.001) | nDCG 0.287 → 0.506 (p<0.001) |
| **토큰화 수정: BM25 기본 분석기 → WordPiece** | 키워드 질의 MRR 0.668 → 0.850 (p<0.001), 다르게 쓴 질의 Hit@20 57.3% → 77.0% (p<0.001) | Hit@20 63.5% → 84.5%, nDCG 0.383 → 0.556 (모두 p<0.001) |
| **상호 보완: BM25 단독 → 하이브리드** | 다르게 쓴 질의 Hit@20 77.0% → 82.0% (p=0.014). 전체는 유의하지 않음(p=0.243) | Hit@20 84.5% → 85.3% (p=0.458, 유의하지 않음) |
| 〃 순위 품질 | MRR 0.731 → 0.515 (하이브리드가 낮음) | nDCG 0.556 → 0.506 (하이브리드가 낮음) |
| **임베딩 모델: 하이브리드(klue) → 하이브리드(ko-sroberta)** | Hit@20 91.9% → 92.7% (p=0.281), MRR 0.515 → 0.596 (p<0.001) | Hit@20 85.3% → **90.2%** (p<0.001), nDCG 0.506 → **0.689** (p<0.001) |

결론은 네 가지다.
1. **Dense 단독이던 원래 방식에서 하이브리드로 바꾼 효과는 두 데이터 모두에서 크고 유의하다.**
2. **BM25 토큰화 수정(WordPiece) 효과도 두 데이터 모두에서 유의하다.**
3. **하이브리드는 BM25 단독보다 정답 후보를 놓치지 않는 쪽으로 낫지만, 그 차이는 다르게 쓴 질의에서만 유의하다.** 순위(1위 맞히기)는 오히려 BM25 단독보다 낮다.
4. **가장 큰 다음 개선 여지는 임베딩 모델이다.** 한국어 문장 임베딩 모델로 바꾼 하이브리드는 공개 벤치마크에서 모든 지표가 가장 높다.

```bash

docker compose -p myanalyst-eval run --rm --no-deps -v ./services/knowledge:/src -v <hf-cache-dir>:/hfcache \
  -e PYTHONPATH=/src -w /src knowledge python -m evals.retrieval_comparison_eval   # 자체 데이터, CPU 약 19분
docker compose -p myanalyst-eval run --rm --no-deps -v ./services/knowledge:/src -v <hf-cache-dir>:/hfcache \

OPENAI_API_KEY=stub docker compose -p myanalyst-eval down -v
```

- **코드:**
  - `retrieval_engine.py`: 색인, 검색, RRF
  - `stats.py`: 지표, 신뢰구간, 검정
  - `retrieval_comparison_eval.py`: 자체 데이터 평가
  - `public_benchmark_eval.py`: 공개 벤치마크 평가
- **격리:** 평가 전용 Milvus 컬렉션과 OpenSearch 인덱스를 만들고 끝나면 지운다. 운영 인덱스(`myanalyst-chunks`)는 건드리지 않는다.
- **결과 파일:** `results/retrieval_comparison.json`, `results/public_benchmark_ko_strategyqa.json`(질의별 상위 20개 순위 포함).

## 비교한 설정

모든 설정은 검색기마다 상위 20개를 가져온다(운영 `SEARCH_TOP_K`). 하이브리드는 RRF(`k`=60)로 합친 뒤 상위 20개를 쓴다.

| 설정 | 내용 |
|---|---|
| `dense_klue` | `klue/bert-base` 평균 풀링 + L2 (현재 운영 임베딩. 원래 시스템은 이것만 썼다) |
| `dense_ko` | `jhgan/ko-sroberta-multitask`(한국어 문장 임베딩용으로 학습된 모델) 평균 풀링 + 코사인 |
| `bm25_standard` | OpenSearch 기본(standard) 분석기로 원문 색인·질의 (토큰화 수정 전) |
| `bm25_wordpiece` | KLUE-BERT WordPiece로 미리 토큰화, whitespace 분석기 (현재 운영) |
| `hybrid` | dense_klue + bm25_wordpiece, RRF 1:1 (현재 운영) |
| `hybrid_bm25x2` | dense_klue + bm25_wordpiece, RRF 1:2 |
| `hybrid_ko` | dense_ko + bm25_wordpiece, RRF 1:1 |
| `hybrid_ko_bm25x2` | dense_ko + bm25_wordpiece, RRF 1:2 |

## 지표와 통계

- **지표:**
  - Hit@k: 정답이 상위 k개 안에 있는 질의 비율. 이 시스템에서 가장 중요한 지표는 **Hit@20**이다. 생성 파이프라인이 검색 결과 20개를 받아 LLM으로 관련성을 다시 채점하므로(Corrective RAG), 정답이 후보 20개 안에만 들어오면 된다.
  - MRR@10: 정답 순위 역수의 평균
  - nDCG@10: 공개 벤치마크(MTEB)의 표준 지표
  - Recall@20: 정답 문단 중 상위 20개에 든 비율
- **신뢰구간:** 부트스트랩 95% 백분위 구간(2,000회). 자체 데이터는 같은 정답 문장에서 만든 질의 3개가 서로 독립이 아니므로, 정답 문장 단위로 묶어 다시 뽑는다.
- **유의성 검정(같은 질의에 두 설정을 돌린 짝지은 비교):**
  - Hit 지표: McNemar 정확 검정. 결과가 갈린 질의만 센다(표의 "a만/b만").
  - MRR·nDCG: 부호 뒤집기 순열 검정(10,000회).
  - 둘 다 양측 검정이다. 자체 데이터의 "전체" 묶음은 질의 3종이 서로 독립이 아니므로 McNemar보다 정답 문장 단위 부트스트랩 구간을 기준으로 본다.

## 자체 데이터 (셀트리온 뉴스)

### 만드는 법

- **문서:**
  - `ingest_sources/셀트리온_news_links_{1,2,3}.txt`의 링크를 순서대로 받는다.
  - 본문 추출 품질 기준을 통과한 기사 **1,300개(청크 6,863개)**를 검색 대상으로 쓴다.
  - 앞쪽 기사에서 정답 문장을 고르고, 나머지 기사는 방해 문서가 된다. 셀트리온 관련 기사가 많아서 검색이 실제처럼 어렵다.
  - 광고 자리 표시 문자열은 지운다. 청크는 문장 단위로 350자 근처에서 자른다.
- **정답 문장 300개(사람이 고르지 않음):**
  - 기사마다 첫 문장을 건너뛴다. 40자 이상이고, 조사가 붙은 어절이 2개 이상이며, 명사 위주 단어가 5개 이상인 문장 중 앞쪽 1개와 가운데 1개를 고른다.
  - 같은 보도자료를 여러 매체가 고쳐 실은 거의 같은 문장(글자 2-gram 겹침 계수 0.6 이상)은 한 번만 쓴다. 사실상 같은 질의가 여러 개 들어가 통계가 실제보다 확실해 보이는 것을 막기 위해서다.
- **질의 3종(같은 정답 문장에서):**

  | 유형 | 만드는 법 | 원문과 겹치는 단어 비율 |

  | `verbatim` | 문장 어절 그대로 앞 5개 | 1.00 |

## 해석

1. **원래 방식(Dense 단독, klue/bert-base)은 약했다.** 자체 데이터에서 키워드 질의의 Hit@20이 0.307이다. `klue/bert-base`는 문장 검색용으로 학습한 모델이 아니어서, 비슷한 기사가 많으면 정답을 찾지 못한다. BM25를 더한 하이브리드가 이 공백을 메웠고(전체 +43.7%p), 사람이 만든 공개 데이터에서도 +24.2%p로 재현됐다.
2. **토큰화 수정은 한국어 BM25의 전제 조건이다.**
   - 기본 분석기는 "252억6000만원으로"를 한 토큰으로 보기 때문에 "252억6000만원"과 맞지 않는다. 그래서 질의와 문서의 어형이 다르면 실패한다.
   - 공개 벤치마크에서 Hit@20이 63.5%에서 84.5%로 올랐다.
   - 반대로 문서 어형을 그대로 쓴 verbatim 질의에서는 기본 분석기가 순위를 더 잘 맞혔다(MRR 0.937 대 0.855). 이 경우에는 통째 토큰이 더 정확하게 일치하기 때문이다. 실제 질의(LLM 키워드, 다시 쓴 질의)는 어형이 다르므로 WordPiece가 맞다.
3. **하이브리드와 BM25 단독은 "놓치지 않음"과 "1위 맞히기" 사이의 교환이다.**
   - 하이브리드는 다르게 쓴 질의에서 BM25가 놓친 정답을 더 찾는다(Hit@20 +5.0%p, p=0.014).
   - 대신 같은 가중치 RRF에서 Dense 쪽이 BM25의 1위를 아래로 끌어내려 MRR·nDCG가 낮아진다.
   - 이 파이프라인은 상위 20개를 LLM이 다시 채점하므로 "놓치지 않음"을 우선해 하이브리드를 유지했다.
4. **BM25 가중(1:2)은 사실상 "BM25 후보 20개를 재정렬"하는 것과 같다.**
   - `k`=60에서 BM25 20위의 점수(2/81 ≈ 0.025)가 Dense 1위의 점수(1/61 ≈ 0.016)보다 크다. 그래서 Dense만 찾은 문서는 상위 20개에 들어오지 못한다.
   - 그 결과 가중 설정의 Hit@20은 두 데이터 모두에서 BM25 단독과 정확히 같다.
   - Dense가 후보를 보태게 하려면 가중치를 1:1에 가깝게 두거나, 후보 수를 늘려야 한다.
5. **다음 개선은 임베딩 모델 교체다.**
   - 한국어 문장 임베딩(`ko-sroberta-multitask`)으로 바꾼 하이브리드는 공개 벤치마크에서 Hit@20 0.853 → 0.902, nDCG@10 0.506 → 0.689로 모두 유의하게 올랐다(p<0.001). 자체 데이터에서도 MRR이 유의하게 올랐다(0.515 → 0.596).
   - 운영에 적용하려면 Milvus 재색인(차원 768로 같음)과 knowledge 서비스 모델 교체가 필요하다.

## 한계

- 자체 데이터의 질의는 기사 문장에서 규칙으로 만들었으므로 어휘 일치에 유리하다. 공개 벤치마크로 이 편향을 보완했다.
- `paraphrase` 300개는 한 사람(평가 작성자)이 썼다. 원문 단어 겹침은 0.42다. 다른 작성자 50개 비교는 아직 하지 않았다.
- 실제 운영 질의(LLM 키워드, `rewrite_query` 결과)로는 측정하지 않았다. 그러려면 OpenAI 호출이 필요하다.
- 같은 사실을 매체마다 크게 다르게 쓴 문장(예: 램시마SC 유럽 점유율 22%)은 중복 필터와 정답 확장에 걸리지 않는다. 그런 문장의 다른 기사 청크가 상위에 와도 오답으로 처리되므로, 모든 설정의 점수가 조금씩 낮게 나온다.
- 규칙 잡음이 있다. 조사 떼기(예: "공매도" → "공매"), 서술어 판별, 본문 추출 모두 일반 규칙이다. 링크 파일에 셀트리온과 무관한 기사(증시 시황 등)도 섞여 있다.
- 공개 벤치마크는 위키백과 계열의 일반 상식 질문이라 금융 뉴스와 영역이 다르다. 경향 확인용이다.
